# RH-29 MACHINE1-Z — evidence gate after Y FIQ banking fix

## Device evidence from MACHINE1-Y

MACHINE1-Y fixed Dyncom shared R8-R12 preservation across SVC↔FIQ. The device trace then changed the bootstrap path materially:

- SVC R11 survives as `0x00000744`.
- At PC `0x12EC`, R1 is `0x744` and `LDR r2,[r1]` reads `0x10`.
- The firmware transforms that to `0x108`, then at `0x2338` derives R2=`0x42` words.
- The copy loop at `0x2340–0x234C` copies 32-bit words from source `0x744` to destination `0x0A000000`.
- Y stops at the fifth destination word, write32 `0x32800021 -> 0x0A000010`, because the pre-existing sparse probe model only covered 16 bytes at that island.
- Low-vector shadow write count is zero in Y. The prior X low-address path was therefore a CPU banking artifact, not evidence for a low-memory remap.

## MACHINE1-Z policy

Z keeps the Y FIQ banking fix and the X 36-byte low-vector shadow unchanged.

It adds one evidence-gated bootstrap-copy view:

- source evidence: `0x00000744`;
- destination base: `0x0A000000`;
- exact size: `0x108` bytes = `0x42` 32-bit words;
- accepted writes: width 32, aligned, PC `0x2344`, LR `0x3C8`, and only inside the exact footprint;
- readback: only bytes already initialized by those accepted writes;
- before the copy, sparse-probe gaps remain unmapped;
- after `0x0A000107`, fail closed.

This does not claim that the entire `0x0A000000` region is RAM and does not assign any new semantics to `0x0C150004`.

## Expected device observation

If the Y-derived copy count is complete, Z should accept 66 copy writes and initialize 264 bytes. The next fail-closed access after that copy is the evidence target for the next model decision. No mapping is added beyond the exact copied footprint.
