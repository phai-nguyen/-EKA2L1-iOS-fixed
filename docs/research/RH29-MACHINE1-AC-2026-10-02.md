# RH-29 MACHINE1-AC — exact initialized post-copy structure writeback

## Evidence from MACHINE1-AB

AB completed the exact second stack push:

- `BOOTSTRAP_NESTED_STACK_WRITE_COUNT=4`;
- `BOOTSTRAP_NESTED_STACK_INITIALIZED_BYTES=16`;
- `BOOTSTRAP_NESTED_STACK_READ_COUNT=4`.

After the helper returns, firmware executes:

- PC `0x11C8`: `LDR r3,[r0,#8]`, with `r0=0x0A000008`, so the read address is `0x0A000010`;
- the read value is the already-copied structure word `0x32800021`;
- PC `0x11CC` and `0x11D0` OR additional control bits, producing `0xB2800021`;
- PC `0x11D4`: instruction `0xE5803008` attempts `STR r3,[r0,#8]`, write32 `0xB2800021 -> 0x0A000010`, LR `0x22C4`.

The destination is inside the existing Z copy footprint `0x0A000000–0x0A000107`; the blocker is therefore a mutation-policy issue, not evidence for a broader address mapping.

## MACHINE1-AC policy

AC preserves all Y/Z/AA/AB behavior and adds only this writeback:

- address: `0x0A000010`;
- width: 32-bit;
- PC gate: `0x11D4`;
- LR gate: `0x22C4`;
- observed instruction: `0xE5803008`;
- observed value: `0xB2800021`;
- precondition: all four destination bytes must already have been initialized by the exact Z bootstrap copy;
- effect: update the existing bootstrap-copy backing store in place.

No new address range is mapped. Wrong value, wrong PC, wrong LR, or a write before copy initialization remains fail-closed.

The probe-share UI remains unchanged: **Chia sẻ báo cáo** is directly below **Chạy probe**.

`0x0C150004` remains semantically unknown; AC makes no remap claim.
