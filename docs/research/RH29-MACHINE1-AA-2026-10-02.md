# RH-29 MACHINE1-AA — exact first bootstrap stack push

## Evidence from MACHINE1-Z

Z completed the Y-derived bootstrap copy exactly as predicted:

- 66 accepted 32-bit copy writes;
- 264 initialized bytes at `0x0A000000–0x0A000107`;
- low-vector shadow write count remains zero.

After the copy, the firmware reads `0x0A000000` from the structure at `0x82C`. At PC `0x3AC`, instruction `0xE280DEFF` computes `SP = 0x0A000000 + 0xFF0 = 0x0A000FF0`.

The next routine begins at PC `0x11A8` with instruction `0xE92D47F0`, decoded as `STMDB sp!, {r4-r10,lr}`. Eight 32-bit registers require 32 bytes, so the exact first push footprint is `0x0A000FD0–0x0A000FEF`. Z fails on the first write at `0x0A000FD0`, width 32, PC `0x11A8`, LR `0x3C8`.

## MACHINE1-AA policy

AA keeps all Y and Z behavior unchanged and adds only this first observed stack push:

- top: `0x0A000FF0`;
- admitted footprint: `0x0A000FD0–0x0A000FEF`;
- write width: 32-bit aligned;
- gate PC: `0x11A8`;
- gate LR: `0x3C8`;
- observed instruction: `0xE92D47F0`;
- readback only for bytes initialized by that exact push.

AA does **not** map the surrounding 4 KiB as generic RAM. Any deeper stack use below `0x0A000FD0`, or unrelated writes in the page, remains fail-closed and becomes the next evidence target.

`0x0C150004` remains semantically unknown; AA makes no remap claim.
